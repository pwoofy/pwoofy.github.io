<h1>To cbrt or not to cbrt?</h1>

You open a crypto challenge, you check the provided scripts, and you see `e = 3`. The immediate instinct is to just $$\sqrt[3]{\text{N}}$$ it and be done, right?

<h2>Type 1: The FREE!!! Version</h2>

Challenge description:
> I encrypted my suuuuper duper secret flag. Good luck factoring my massive 1024-bit modulus! Mwehehehe.

<div class="sage">
  <script type="text/x-sage">

p = random_prime(2^512)
q = random_prime(2^512)
N = p * q
e = 3
flag = b"crypto{ooh}"
m = int.from_bytes(flag, 'big')
C = power_mod(m, e, N)
print(f"N = {N}")
print(f"C = {C}")
  </script>
</div>

<details>
  <summary><b>💡 Interactive: How do we solve this? (Click to reveal)</b></summary>
  Let's look at the textbook RSA encryption formula:
$$C \equiv m^e \pmod N$$

If the message $m$ is relatively short, and $e$ is only $3$, then $m^3$ has a chance to be *smaller* than the massive modulus $N$. <br><br>

But what does this mean? Let's look at an example.<br><br>

Let's say that you have a message. For simplicity's sake, we assume our message is a singular number. Let's say the number is 40. And if we take our p and q as a really large prime. For simplicity's sake, let's assume that $p*q$ is 1 million (1,000,000). What does this do?

Well, going back to the following formula:

$$C \equiv m^e \pmod N$$

Our ciphertext would be $40^3 \pmod {1000000}$, or $64000 \pmod {1000000}$. What does this mean?
  <br>
  Since the modulo didn't wrap around, the ciphertext $C$ is literally just the raw $m^3$. <br><br>
  You don't really need to factor the modulus or find the private key. You literally just take the standard integer cube root of $C$ to recover the flag.
</details>

<br>
<h3>Try it live!</h3>
The following block of code can be ran for your own interest, if you are curious as to how it works! (Solve script is written in SageMath)

<div class="sage">
  <script type="text/x-sage">

print(f"Flag: {recovered_bytes.decode()}")
  </script>

<h2>Type 2: The Free(n't) flag...</h2>

Challenge description:
> I figured out the cube root trick, so I padded the message with some extra text at the front. Good luck now!
<br>
> Prefix: "i_pad_this_part_lol: "

<div class="sage">
  <script type="text/x-sage">
p = random_prime(2^512)
q = random_prime(2^512)
N = p * q
e = 3
prefix = b"i_pad_this_part_lol: "
flag = b"crypto{winner_but_i_pad_the_message}"
m = int.from_bytes(prefix + flag, 'big')
C = power_mod(m, e, N)
print(f"N = {N}")
print(f"C = {C}")
  </script>
</div>

<details>
  <summary><b>💡 Interactive: How do we do this? (Click to reveal)</b></summary>
  Let's go back to our formula:
$$C \equiv m^e \pmod N$$

By adding a prefix, the author has made our message $m$ much larger. To solve this, we define a polynomial where our unknown flag is $x$:
$$f(x) = (\text{prefix} \cdot 2^k + x)^3 - C \equiv 0 \pmod N$$

Wellllll...that's complex. Let's simplify it a bit more.

Let's shrink everything down to see the problem. Imagine our modulus is 323. Our known prefix is 10, and our secret PIN $x$ is 2. The total message is 12.<br><br>
$12^3 = 1728$. <br>
1728 modulo 323 is 113. So our ciphertext is $C = 113$.<br><br>

So now, our polynomial looks like this:
$$f(x) = (10 + x)^3 - 113 \equiv 0 \pmod{323}$$

If we expand that using basic algebra, we get:
$$f(x) = x^3 + 30x^2 + 300x + 887 \equiv 0 \pmod{323}$$

We can simplify 887 by modulo-ing it 323, leaving us with the polynomial of:
$$f(x) = x^3 + 30x^2 + 300x + 241 \equiv 0 \pmod{323}$$

"Can't we just solve this with simple algebra to find $x$"? Well, No. Maybe? Yes? If you plug $x = 2$ into that equation using normal math, you get 969. Mod 323 and you get 0. In mod 323, 969 is equal to 0 (because 969 mod 323 is 0). However, you can't just use a standard algebraic solver, cause it won't be able to know that substituting x = 2 is a valid answer. It just sees the answer as 969, which isn't 323, so it considers x = 2 an invalid answer when it should be valid (cause again, 969 mod 323 is 0).<br><br>

Enter Howgrave-Graham's Theorem. The theorem states that if we have a polynomial equation $f(x) \equiv 0 \pmod{N}$ and a set bound X on the size of its' root ($|x_0| \leq X$), then the magnitude of the polynomial evaluated at its X will always be strictly less than N ($f(xX) \lt \frac{N}{\sqrt{d+1}}$), where d is the degree, and the modulo vanishes, which means that the equation becomes $f(x_0) = 0$ over standard integers.

To allow this to happen, we need to build a lattice. Think of a lattice as an infinite grid of dots, and every point on this infinite grid is created by mixing and adding together a set of vectors. <br><br>

Here, we want to find a new polynomial that evaluates to $0 \pmod N$. So we feed our lattice with a set of polynomials that we already know equals to $0 \pmod N$. 

For example:
<ul>
  <li>$N$ is a multiple of $N$, so $N \equiv 0 \pmod N$.</li>
  <li>$N \cdot x$ is just $N$ times something, so it is also $\equiv 0 \pmod N$.</li>
  <li>$N \cdot x^2$ is also $\equiv 0 \pmod N$.</li>
  <li>And our polynomial $f(x)$ is what we are trying to solve, so $f(x) \equiv 0 \pmod N$.</li>
</ul>

Because every row in our matrix equals to 0 mod $N$, every single point in the lattice represents a combination of polynomials that also equal to 0 mod $N$.<br><br>

There's a problem though, and it's the fact that LLL doesn't know that $x$ is a variable that can grow exponentially quick. To force it to respect higher powers of $x$ are computationally (and mathematically) heavier, we apply an $X$ to the columns, where $X$ is the absolute maximum size we think our secret $x$ could be. Let's take a gamble and say that $X = 5$ (way higher than x = 2, which is what we want to have).<br><br>

We build our 4x4 matrix row by row. Each column represents a power of $x$ ($x^0, x^1, x^2, x^3$), scaled by our $X$ value:
<ul>
  <li>Row 1 ($N$): 323, 0, 0, 0</li>
  <li>Row 2 ($Nx$): 0, $323 \cdot 5$, 0, 0 $\rightarrow$ <b>0, 1615, 0, 0</b></li>
  <li>Row 3 ($Nx^2$): 0, 0, $323 \cdot 5^2$, 0 $\rightarrow$ <b>0, 0, 8075, 0</b></li>
  <li>Row 4 ($f(x)$): 241, $300 \cdot 5$, $30 \cdot 5^2$, $1 \cdot 5^3$ $\rightarrow$ <b>241, 1500, 750, 125</b></li>
</ul>

This is exactly what SageMath is doing in the background! There is a catch though. If you run LLL on this exact matrix with $X = 5$, it fails because the numbers in the matrix are too heavy. If we reduce our $X$ to 3, the math shrinks just enough to make running LLL on the matrix feasible. SageMath script attached:

<div class="sage">
  <script type="text/x-sage">
N = 323
X = 3

M = Matrix(ZZ, [
    [N,   0,       0,         0],
    [0,   N*X,     0,         0],
    [0,   0,       N*(X^2),   0],
    [241, 300*X,   30*(X^2),  1*(X^3)]
])

reduced_M = M.LLL()
sv = reduced_M[0]

coeffs = [
    sv[0] / (X^0),
    sv[1] / (X^1),
    sv[2] / (X^2),
    sv[3] / (X^3)
]

P.<x> = PolynomialRing(ZZ)
np = sum(coeffs[i] * (x**i) for i in range(4))
roots = np.roots()

print(f"PIN Code: {roots[0][0]}")
  </script>
</div>

As we can see, the $N$ goes away, and the result hands us the secret key. This is practically similar to when you use `.small_roots()` on a real CTF challenge, which is just automating this exact matrix construction (and expanding it to be much larger to handle bigger $X$).
</details>

The following block of code runs both the server generation and the LLL attacker script. (Solve script is written in SageMath)

<div class="sage">
  <script type="text/x-sage">
p = random_prime(2^512)
q = random_prime(2^512)
N = p * q
e = 3

prefix = b"i_pad_this_part_lol: "
flag = b"crypto{winner_but_i_pad_the_message}"

m_int = int.from_bytes(prefix + flag, byteorder='big')
C = power_mod(m_int, e, N)

print(f"N = {N}")
print(f"C = {C}")
print(f"Known Prefix: {prefix}")

k_bits = 288  
X_gamble = 2^k_bits

prefix_int = int.from_bytes(prefix, byteorder='big')
base_message = prefix_int * (2^k_bits)

P.<x> = PolynomialRing(Zmod(N))
f = (base_message + x)^e - C
f = f.monic()

print(f"Building lattice matrix and running LLL...")
roots = f.small_roots(X=X_gamble, epsilon=0.03)

if roots:
    secret_x = int(roots[0])
    recovered_bytes = secret_x.to_bytes((secret_x.bit_length() + 7) // 8, byteorder='big')
    print(f"\nflag: {recovered_bytes.decode()}")

  </script>
</div>

<h1>Final Thoughts</h1>

If $m^3 < N$, just cube root it and take your points. If $m^3 > N$ and you know part of the plaintext, you have to let LLL do the heavy lifting. Once you understand what the `small_roots` function is actually doing under the hood, these Crypto challenges become incredibly satisfying to solve, hehe :3c
