# Big modulus, small secret

When a challenge hands us a huge RSA modulus, factoring it sounds like the obvious first step. But before trying to factor anything, let's ask a different question:

> How were the primes in the modulus generated?

Here, the generator makes lots of primes, but each one comes from a Python `random.Random` instance seeded with a value chosen from a range that depends on a small parameter. The important detail is that the parameter bounds the **seed**, not the prime size. Some of those seed ranges are tiny enough to search.

## What does the modulus tell us?

In RSA, the modulus $N$ is built from prime factors, and the ciphertext $C$ encrypts a message integer $m$:

$$
N = \prod_i p_i
\qquad\text{and}\qquad
C \equiv m^e \pmod N
$$

Ordinarily, recovering the factors $p_i$ from $N$ is meant to be difficult. But if we can reproduce one of the primes, we can test it directly:

$$
p_i \mid N
\quad\Longleftrightarrow\quad
N \bmod p_i = 0
$$

So instead of factoring $N$, we can try to reproduce the prime generator.

## Step 1: Read the key-generation code

Here is the challenge's key-generation logic:

```python
from math import prod
from secrets import randbelow
import random

from Crypto.Util.number import isPrime, bytes_to_long


def get_prime(n):
    p = 1
    r = random.Random()
    print(f"Generating prime with {n} bits...")
    r.seed(randbelow(2**n))
    while not isPrime(p):
        p = r._randbelow(2**256) | 1
    return p


flag = open("flag.txt", "rb").read().strip()
assert len(flag) == 128
N = prod(get_prime(i) for i in range(2, len(flag)))
print(hex(N), hex(pow(bytes_to_long(flag), 0x10001, N)))
```

Let's unpack it line by line.

### The seed is the weak link

For each call to `get_prime(n)`, the code does this:

```python
r = random.Random()
r.seed(randbelow(2**n))
```

`randbelow(2**n)` chooses an integer from $0$ up to (but not including) $2^n$. The `secrets` module makes that choice unpredictable, but the number of possible seeds is still only $2^n$.

For example, when $n=2$, there are only four possible seeds: $0,1,2,3$. We can simply try each one. The seed space grows with $n$, so later calls are harder to guess, but the earliest calls have very little seed entropy.

### The prime itself is generated deterministically

After seeding, the code repeatedly generates odd candidates:

```python
p = 1
while not isPrime(p):
    p = r._randbelow(2**256) | 1
```

The `| 1` operation sets the least significant bit, ensuring the candidate is odd. The loop continues until `isPrime` accepts a candidate.

For a given seed, this sequence of candidates is deterministic: recreate the same `random.Random` state and we get the same prime. Notice that `2**256` is an upper bound for the candidates; it does not force them to be exactly 256 bits long.

### Many primes make the modulus

The flag is asserted to be exactly 128 bytes long. Python's `range(2, len(flag))` stops before its endpoint, so it calls `get_prime` for $n=2,3,\ldots,127$: 126 calls in total.

$$
N = \prod_{n=2}^{127} \operatorname{get\_prime}(n)
$$

Some calls could even produce the same prime if their seed choices happen to match. We do not need to recover every factor, though. Since the flag is 128 bytes, its integer representation satisfies:

$$
0 \leq m < 2^{8\cdot128} = 2^{1024}
$$

If we recover distinct prime factors whose product $Q$ is greater than $2^{1024}$, their combined congruences are enough to identify $m$ uniquely.

## Step 2: Search for reproducible primes

The attack guesses seeds, recreates the first prime produced by each seed, then checks whether that prime divides $N$. It does not have to know which call used the seed: divisibility is the test.

The values `N_hex` and `C_hex` below are the hexadecimal values printed by the challenge. Paste them into the two strings before running the script.

```python
import random
from math import prod

from Crypto.Util.number import isPrime, inverse, long_to_bytes
from sympy.ntheory.modular import crt

N_hex = "PASTE_N_HERE"
C_hex = "PASTE_C_HERE"

N = int(N_hex, 16)
C = int(C_hex, 16)
e = 0x10001

recovered_primes = []
seed = 0
message_bound = 2**(8 * 128)

while prod(recovered_primes) <= message_bound:
    r = random.Random()
    r.seed(seed)

    p = 1
    while not isPrime(p):
        p = r._randbelow(2**256) | 1

    if N % p == 0 and p not in recovered_primes:
        recovered_primes.append(p)
        print(f"[+] Found distinct prime for seed {seed}: {p}")
        print(f"    Recovered product is now {prod(recovered_primes).bit_length()} bits")

    seed += 1
```

Each iteration asks, “If the generator had been seeded with this value, what prime would it produce?” If the result divides $N$, it is one of the modulus's factors. We keep only distinct primes because repeating a factor does not increase the modulus of our later CRT reconstruction.

The stopping condition is important. Five factors may be enough if their product exceeds $2^{1024}$, but the code should check that rather than assume it. When $Q=\prod p_i > 2^{1024}$, the real message integer is the only number in its possible range that has all the recovered residues.

This seed search is practical for the challenge instance because the key generator includes calls with small seed spaces. It is not a general way to factor arbitrary RSA moduli: if the useful seeds are too large, trying them one by one is infeasible.

## Step 3: Decrypt modulo each recovered prime

For each recovered prime $p_i$, the RSA equation also holds modulo $p_i$:

$$
C \equiv m^e \pmod {p_i}
$$

When $e$ has an inverse modulo $p_i-1$, define the local private exponent:

$$
d_i \equiv e^{-1} \pmod {p_i-1}
$$

Fermat's little theorem then lets us recover the message modulo that prime:

$$
m_i \equiv C^{d_i} \pmod {p_i}
$$

The script computes one residue for each factor:

```python
moduli = []
remainders = []

for p in recovered_primes:
    d_local = inverse(e, p - 1)
    m_local = pow(C, d_local, p)

    moduli.append(p)
    remainders.append(m_local)
```

Each pair says that the original message has a particular remainder:

$$
m \equiv m_i \pmod {p_i}
$$

## Step 4: Combine the residues with CRT

The Chinese Remainder Theorem combines those congruences into one value modulo the product $Q$ of the distinct recovered primes:

$$
m \equiv m_i \pmod {p_i}
\quad\text{for every } i
\quad\Longrightarrow\quad
m \equiv M \pmod Q
$$

Because the primes are distinct, they are pairwise coprime, which is exactly what CRT needs. And because our search stopped only after $Q > 2^{1024}$, while the 128-byte flag integer satisfies $m < 2^{1024}$, the CRT result is the message itself—not merely an ambiguous residue.

```python
print("[*] Applying Chinese Remainder Theorem (CRT)...")
M, _ = crt(moduli, remainders)
M = int(M)

print("\n[+] Recovered flag:")
print(long_to_bytes(M).decode("utf-8"))
```

This step requires `inverse(e, p - 1)` to exist. The supplied solve script assumes it does for the recovered factors; if the inverse fails for a factor, that factor cannot be decrypted with this particular step.

## Putting it all together

The full attack is a chain of small ideas:

1. The generator chooses a seed from a range of size $2^n$.
2. For small $n$, enumerate possible seeds and reproduce their deterministic primes.
3. Use divisibility, $N \bmod p = 0$, to recognize factors.
4. Decrypt the ciphertext modulo each recovered prime.
5. Combine those residues with CRT until the product of the factors is larger than the maximum possible plaintext.

The RSA operation itself is not the weakness. The problem is that some of the prime-generating seeds have such small search spaces that we can reproduce the factors without factoring the modulus.

___

# Final thoughts

The surprising part wasn't the size of $N$; it was the range used to seed the generator. `secrets` is a secure way to choose a seed, but choosing from only four possibilities still leaves just four possibilities to try.

For real RSA key generation, use a well-tested cryptographic library that generates keys with cryptographically secure randomness. Do not build key-generation logic from `random.Random`, and do not assume that a secure random source can make a tiny seed space safe.
